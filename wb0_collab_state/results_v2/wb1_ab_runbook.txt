2. **G2 组合 sha256**：按 fingerprint 定义的拼接序（per_file 列表顺序）计算组合 sha256 = `19ad7098…`。

   故 **G2 降级为记录值**：硬闸门以 G1（9/9 逐文件）为准（密码学强度等价），
   combined_sha256 作为记录值上报，不作硬闸。
3. **G3 冻结件核验**：`sha256sum bundle/src/shared/semantic_router.pt` = `4b4f1064b17b1af9…`。

### S3 确定性建图（60 实体 / 40 查询 / 黄金中间节点；seed=20261020）
数据源：`data/2wikimqa.jsonl`（200 条，LongBench 原生格式：input/context/answers/_id）。
构造规格（确定性，全部随机性只来自 seed=20261020 的固定 Generator）：
1. 逐条解析 context：按 `Passage \d+: ` 切分；每条取首句为 title（实体名），其余为 text。
2. 实体节点 = 规范化 title（小写、去标点、空白折叠）；全局去重。
3. 有向边 A→B：A 的 text 中出现 B 的规范化 title（实体共现图，方向按 Passage 出现序）。
4. 查询 = 样本 `input`；黄金答案 = `answers[0]` 的规范化实体。
5. 黄金中间节点：从查询主语实体（在 question 中出现的 title 实体）出发，在共现图上
   找一条长度 ≤3 的路径到达黄金答案实体；路径的中间节点即 gold intermediate（PR@5 的目标）。
   只保留**存在 2 跳路径**（主语→中间→答案）的查询 —— 2wiki 数据集定义即二跳。
6. 用固定 Generator（seed=20261020）对合格查询洗牌，取前 **40** 条为查询集；
   其诱导子图内的实体去重后取 **60** 个（不足 60 则如实记录实际数，并在产物中披露；
   超过则按查询覆盖度排序取前 60）。边数如实记录（proxy 为 247，真实值以构造结果为准）。
7. 落盘 `out/multihop_real.json`：{n_ent, n_queries, n_edges, entities[], queries[{qid, question, subject, gold_intermediate[], answer}], edges[[a,b]…], seed, construction: "2wikimqa-passage-title-coccurrence"}。
   **披露义务**：此图与 proxy 的 multihop_20261020.json 构造不同（proxy 文件不在 Hub），
   必须在产物 honesty_note 中说明构造方法与差异。

### S4 环境保真闸门（G4 元数据 + G5 R32 基线复现，均为硬闸门）
**G4 元数据交叉核验**（全部可离线核对，无需跑模型）：
- bundle 内 `real_features_3b.json` 自身 sha256 = `84e37106e7e111e801294c45dc7d3910948d08d104561793a82acc7430e5b261`；
- 与 Hub 上 `r2_layer_sensitivity_3b`（R32）配置一致性：model 路径一致、
  hidden_size=2048、group_layer=final、target_layer=12、GSC 参数 k=16/tau=0.97/centered、
  paragraphs=8/repeats=6 一致（n_tokens 2586 vs R32 的 2613 属不同次导出，记录两者即可，不算不一致）；
- 任一不符 → open_item 停止。

**G5 R32 基线复现**（本闸门是"执行器沙盒 ≡ WB1 研究会话"的最强证据）：
R32 的输入构造完全确定性且代码在 bundle 内（`v41_torch_native_runner.build_structured_input`
= TOPIC_TEXTS 常量 + default_rng(seed) 置换，无未公开输入）：
```python
import sys; sys.path.insert(0, "bundle/src"); sys.path.insert(0, "bundle/src/semantickv")
from v41_torch_native_runner import build_structured_input
ids, lab, lab_occ, needle_pos, q_start = build_structured_input(
    tok, n_paragraphs=8, repeats=6, target_tokens=8000,
    needle="请注意，一个重要事实：小王最喜欢的数字是 42。", needle_frac=0.5,
    question="小王最喜欢的数字是多少？请只回答数字：", seed=7)
# R32 输入含答案 token（teacher forcing）：拼接 [19, 17] 到序列尾
ids = torch.cat([ids, torch.tensor([[19, 17]])], dim=1)
# 应得 n_tokens=2613, q_start=2600（与 R32 公布值核对；不符 → open_item 停止）
with torch.no_grad():
    logits = mdl(ids).logits[0].float()          # (N,V)
# loss_answer：答案 token [19,17]（"42"）的 CE。问长 qlen = N-2600-2 = 11，
# 答案位置 ans_pos1=q_start+qlen-1（预测19）, ans_pos2=q_start+qlen（预测17）。
# R32 未公布精确平均方式，按显然候选依次尝试并记录哪个命中：
#  候选1 mean(CE(ans_pos1→19), CE(ans_pos2→17))；候选2 sum；候选3 仅19；候选4 仅17
# 对照 R32 baseline.loss_answer = 0.0017654983093962073
```
判定（WB0 干跑实证 2026-10-21 15:02，权重经 G1 9/9 验证的同权重）：
- **硬闸门**：n_tokens=2613 且 q_start=2600（构造确定性）——不符 → open_item 停止。
- **强证据软闸门**：最佳候选（通常为 c1_mean）与参考值相对差 **≤5%** → env_fidelity=HIGH。
  WB0 干跑实测：同权重下 c1_mean=0.0017857537604868412，与参考值相对差 1.15%
  （归因于跨沙盒 transformers 版本 bf16 CPU 内核微差；错误/损坏权重会是数量级偏差）。
- 相对差 >5% → 记录实际值，发 open_item 报告，由 WB0 裁定放行与否；不放行则记为
  env_fidelity=UNVERIFIED 并在 honesty_note 披露——不自动阻断 S5（S5 判据不依赖 R32 数值）。

  {stage, ts, gates_passed[], next_action, partial_artifacts[]}。下次被激活时**先拉它**，
  已完成的阶段跳过（幂等）。权重 6GB 已下载过则不必重下（检查 models/ 目录 9 文件 sha256 在即用）。
- 7200s 将耗尽仍在 Stage 1 中途：推 status（next_action 精确到子步骤）+ 已产出局部文件，下轮续跑。
- 绝不在同一阶段内重复推送冲突版本；更新即覆盖同一 relpath，回执只交终版一份。

## 4. 铁律（违反 = 任务失败）
────────────────────────────────────────────────────────
1. **无实物不声称**：每个数字必须能追到 Hub 上的实物文件；追不到就发 open_item 说明缺什么。
2. **不伪造**：任何 gate 失败都如实上报失败级别；禁止用 proxy 数字冒充真实 A/B。
3. **D3 环境标签**：所有产物必须带 environment 块（cpu/transformers/torch/smoke 输出），
   不同环境结果不得混用。
4. **determinism_PA11**（实验 ENV-EXP）：import 前单线程 BLAS、seed=20261020、固定 Generator、
   SHA256 记录，缺一不可。诊断 ENV-DIAG（R32 对齐：bf16/4线程/seed=7）仅用于 S2/S4 保真，
   其结果不得混入 ENV-EXP 产物（双标签分别记录）。
5. **冻结件只读**：semantic_router.pt 只加载不重训不覆盖；B 侧 Router 另存新文件。
6. **代理≠结论**：H-WB2-E2E-01 升级只认本 runbook 的真实 A/B 三件套（数据+回执+报告）。
7. 用户零中转：全程不得要求用户传文件；资源一律 Hub/ModelScope 自取。

## 5. 故障路由
────────────────────────────────────────────────────────
- Hub 不可达 → 重试 3 次（间隔 60s）→ 仍失败则发 open_item（target=WB0）并退出，勿空转。
- ModelScope 单文件下载失败 → 该文件重试 3 次；仍失败 → open_item（附 HTTP 状态码）。
- transformers 加载权重报错 → 核对 9 文件 sha256（G1）→ 仍错 → open_item，勿跳过 gate。
- 400/422 类 Hub 接口错误 → 检查是否用了 `-F "body=@file"`（应按字段值发送用 `<file`）；
  relpath 与回执 data_source 必须一致。
- 本 runbook 自身歧义 → 以 hypothesis_ledger.yaml 的 H-WB2-E2E-01 criterion 与
  DEC-20261021-E2E-GATE 为上位依据；仍歧义 → open_item 请求 WB0 裁定，勿自行扩权。
