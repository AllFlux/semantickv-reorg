# 理论背景（Why）

1. **Router 架构已经不是问题**。WB2 用低秩几何证明泛化间隙从 0.26 降到 0.015——
   即模型本身有能力，之前表现差是**训练数据**的问题，不是结构问题。
2. **7B 真实特征导出（Step 6）是当前整个项目唯一破局点**，且「不需要任何更多的
   代理数据」。

这与 WB1 在 DS-029 轮提出的 GAP-DS26-02 完全一致：WB2 现有权重是在
`proxy_data=true`（64 个正交质心 + 高斯噪声、离线 K-means 标签）上训的，
属于**用自己造的分组证明自己会分组**的循环论证。真实 3584 维隐状态 + 真实 GSC
标签，是唯一能打破该循环的输入。

## 反直觉与异常观测

### 1. 「最小部署包」第一次并不最小，反而缺文件

按 import 关系列了 4 个 `.py`，看起来完整。但解压到空目录一跑就崩：
`mock_grouper.fit` 在函数体内部才 `from eval_runner import GroupAssignment`——
**懒加载不体现在顶部 import，静态阅读看不出来**。
教训：依赖清单不能靠读 import 生成，必须**在干净环境里实跑一次**。

### 2. 加 `autodl-7b` 不是加一个字符串，是加一处逻辑分支

若把环境名硬编码成 `if env == "kaggle-7b"`，新增平台就要改多处、容易漏。
故把判断抽成 `compute_env_claims()` + `validate_env_label()` 两个纯函数，
标签集合变成 `AUTHORITATIVE_ENVS = {"kaggle-7b", "autodl-7b"}`，
新增平台只改一行，且能用单测覆盖全部拒绝分支。

### 3. 「维度严格 (N,3584)」这条验收，只能靠断言守住

`--expect-dim` 若只写进文档，任何人跑 0.5B 时都会得到 `(N,896)` 而毫无提示。
把它做成 `env in AUTHORITATIVE and true_dim != expect_dim → return 4`，
才真正把「严格」变成不可绕过。负向测试已确认：不产出任何文件。
