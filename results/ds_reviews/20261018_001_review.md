# 理论背景（Why）

分析 v0.1.2 真实模型慢速验证结果：V0 重排不变性 cos=1.000000（Triton 化数学前提已过），但端到端 final_hidden cos=0.4199、argmax 一致率仅 2.32%，needle 三位置全失败（0.5B 中段基线自身不可靠）。DeepSeek 诊断四类根因：(1) flat-mean 抹杀局部细节；(2) 全层（1-12 层）应用太激进，底层语法树崩坏；(3) τ=0.97 暴露真实隐状态严重各向异性（余弦失效）；(4) 0.5B 容量脆弱。

# 具体步骤（What）

给 WorkBuddy 的修正指令：
1. 废弃 flat-mean，改用三种保护性压缩（V1.5）：代表 Token 法（Top-K，每群保留 Attention 最高的 K=2 或 4 个真实 KV）、加权重构法（Attention-Weighted Sum）、Attention Sink 保护（前 4 token + 最近滑窗不压缩）。
2. 层级选择性压缩：12 层模型仅第 6-10 层应用语义群压缩，底层（1-5）与顶层（11-12）保持原样。
3. 修复距离度量：抛弃余弦（各向异性致坍缩），改用 L2 欧氏距离，或算余弦前先减中心向量（Centering）。
4. Kaggle 7B 预案：先测 Qwen2.5-7B 无压缩基线 needle，确认原始命中正常后再挂载 V1.5；显存监控加 `torch.cuda.memory_reserved`。

# 验收标准（How）

- 端到端 cos 从 0.42 飙升到 0.85 以上（见 H-DS1）。
- 上 Kaggle 后 7B 实打实省 50% 显存且 needle 不崩 → 可写顶会论文。
- 数学地基已夯实（V0=1.0），上 GPU 写 Triton 算子只是时间问题。
