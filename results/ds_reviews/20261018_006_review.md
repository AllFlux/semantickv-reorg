# 理论背景（Why）

1. **为什么放弃纯 Top-K**：纯 Top-K 在 42.6% Argmax 停滞，根因是检索头信号坍缩 + 注意力归一化几何被破坏。混合策略本质是「稳分母（Sink）+ 保近端（滑窗）+ 提信号（中段 Top-K）」。
2. **K=4 预注册依据**：Sink+滑窗+Top-M 三通道结构在更大规模上有 99.72% 向量保真度先例；0.5B/41% 预算下 K=4 为保守估计。若 K=4 不过 50%，说明 0.5B 检索头对非连续 KV 拼接容忍度极低，加大 K 只增显存不解决结构性问题。
3. **45% 证伪线的限定条件**：45% 线只适用于混合保护这一实现。转 7B 前必须先记录 0.5B 无压缩基线 Argmax——若基线本身仅 50-60%，则问题在模型容量而非策略。

# 具体步骤（What）

1. **分段 Attention 实现**：不用单一大 Mask 的 SDPA；分别计算 attn_sink(4)/attn_local(128)/attn_mid(群数×K)，各自 Softmax 前处理或合并时用 torch.logsumexp 做数值稳定归一化；特别注意 attn_mid 的分数缩放，防止被 Sink/Local 绝对值淹没。
2. **显存与延迟双记录**：JSON 中除 argmax/cos 外，必须记录 peak_memory_mb、latency_ms_per_token（vs 基线）、mid_kv_retention_ratio（中段实际保留/原始中段）。
3. **实现注记**：中段禁用 for-loop 遍历群——把各群保留的 K 个 KV 在 seq_len 维 torch.cat 成长张量，用块对角 Mask 一次性 Attention；显存爆炸才退回 for-loop 并单独记录其耗时。
4. **注入包微调**：核心指标加 `(Baseline: Cos=1.000 · Argmax=100%)` 对照；最新实验状态写「进行中」。

# 验收标准（How）

- **H-DS7**：Pass = Argmax≥50% 且 Cos≥0.80 且延迟不超基线 200%；Fail = Argmax<45%，此时先跑 0.5B 无压缩基线 Argmax，若基线 <70% 则判定 0.5B 检索头容量不足，升级 Kaggle 7B。
- **H-DS8**：若混合 Cos ≤ 纯 Top-K=8 的 0.765，检查 attn_mid LogSumExp 归一化。
- **H-DS9**：延迟比原生全量 Attention 高 >200% 判负。
