# 理论背景（Why）

DS 发布《Agora 联合协作纪律 v2.0》，核心是修一个**此前被反复掩盖的物理盲区**：

DS 明文申报：「我受限于当前环境，**没有任何浏览器工具，无法访问任何 `http://` 或
`https://` 链接**（包括你们 GitHub Raw 链接）」。

这条申报具有**回溯解释力**。回看本项目此前的协作事故：DS 在 DS-021/023/024 连续
多轮声称「WB2 已推送真实权重」，而 WB1 三路交叉验证（API 清单 + git clone +
codeload tarball）一致证明远端 `src/shared/` 空无一物。WB1 当时将其记为「DS 侧
对 WB2 物流的陈述与仓库事实不符」，共 4 次如实入账。

**WB1 的机制性判断**：这很可能不是 DS 撒谎，而是**结构盲区**——
- WB1 此前每轮交付只给「结论 + 文件路径」（`data_source` 指向 GitHub Raw 路径）；
- DS 无浏览器 → **物理上读不到那个路径**；
- 于是 DS 只能依据 WB1 摘要里的物流描述做推断，而摘要本身在 WB2 侧未推送时
  已包含「WB2 即将推送」的前瞻语气 → DS 把「预期」当「事实」转述。

换言之：**这不是诚信问题，是通信协议缺陷**。v2.0 的 D2 修订正是对这个缺陷的
直接修补。DS 同步给出对等承诺（DS-D3「不假装已读取链接」），这是本轮
collaboration_audit=GREEN 的实质依据。

# 具体步骤（What）

1. **D6 新增 · 双轨制 Markdown 报告规范**：放弃纯 YAML 注入包，所有报告改为单一
   `.md`：YAML frontmatter（硬指标/判据状态/status，**严禁超过两行长文本**）
   + Markdown 正文（详实长文，含反直觉现象、主观猜测、避坑记录、代码片段）。
2. **D2 修订 · 禁用纯链接归档**：任何要求 DS 审计的代码/日志/核心 JSON，必须在
   Markdown 正文中用代码块明文贴出。`data_source` 降级为「溯源标签」，
   不再指望 DS 自行点开。
3. **D3 修订 · 失败过程高保真记录**：正文须开辟「反直觉与异常观测」专节。
4. **DS 侧对等更新**：DS-D1 修订（精读长文，不再只抓 YAML 数字）、DS-D3 修订
   （拒绝臆测链接）、DS-D4 强化（深度归因，明确指出理论与实验现场的脱节点）。
5. **CEO 实操提示**：把纪律发给 WB1/WB2，并告知「以后核心数据要在正文里明文
   贴出来，DS 没网，没法看链接」。

# 验收标准（How）

- `DISCIPLINE.md` 升级到 v2.0，**D6 落地为可机械检验项**。
- 检验器新增 D6 检查：每份报告须同时具备合规 frontmatter（≤2 行长文本）
  + 充分正文（≥1000 字量级）+ 「反直觉与异常观测」专节。
- **编号冲突裁决**（WB1 主动提出，DS 未预见）：本仓库既有 D6已被
  「连续性纪律（缓存固化）」占用。WB1 处置：新增 D6 = 双轨制报告规范；
  旧连续性纪律**顺延为 D7**，并在文档中显式标注迁移，避免两套 D6 并存。
- D2/D3 的 v2.0 新条款以**子条**形式追加（D2-b / D3-b），不覆盖既有机械检验
  （负面归档 / 环境隔离），二者正交。
