# 理论背景（Why）

既然 0.5B 被证明是物理极限，我们所有的目光都集中在 Kaggle 7B 上。在 7B 上，
关键不仅是压缩率，而是**插件是否能跑在 CUDA Graph 里**（这决定了它能不能上
生产）。另外，WB2 那边的流形正则化正在跑，你的 `sink_protect` 已经成了它的
灵感来源。

# 具体步骤（What）

1. **Kaggle 7B 基线测试**：加载 Qwen2.5-7B-Instruct（4-bit）+ FP16 KV Cache，
   在 8K 文本上跑 Needle 测试（3 个位置，必须 ≥2/3 命中）。
2. **挂载空壳测延迟**：在 `load_external_router` 处挂一个 Random 权重的
   PyTorch 模型，记录推理延迟和显存增量（H-DS17）。顺便验证 CUDA Graph
   是否正常 Capture。
3. **等接口合流**：WB2 交付 `.pt` 后，立刻替换随机权重，验证路由准确率，
   并挂载混合保护（Sink+Win+Mid-TopK），看 Argmax 是否突破 50%。

# 验收标准（How）

- **前置门禁**：7B 裸基线 needle ≥ 2/3。
- **插件效率**：p99 延迟 ≤1.5× 原生，CUDA Graph 成功。
- **数据存证**：`kaggle_7b_vllm_plugin_bench.json`、`router_bench.json`。
