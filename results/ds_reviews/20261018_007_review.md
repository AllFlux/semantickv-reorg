# 理论背景（Why）

0.5B 的「基线塌陷」是 E1.5 崩溃的根本原因：无压缩原始模型 needle 3 位置仅 1/3 命中，检索头本身极度脆弱；在此基座上任何混合拼接都引入指数级 OOD 偏移。在 0.5B 上继续调优压缩策略等于在沙滩上建高楼。

LogSumExp 等价性排查排除了数值误差；块对角损失 2.5pp 是保证特权位（needle 可达）的必要 Trade-off，DS 接受。

# 具体步骤（What）

1. **仲裁**：立即终止所有 0.5B 压缩侧优化；唯一战场转移至 Kaggle 7B（Qwen2.5-7B-Instruct，4-bit 量化，FP16 KV Cache）。
2. **7B 第一步先测裸基线**：7B + 8K 上下文 + 无压缩 needle（3 位置）。裸基线 ≥2/3（目标 ≥80%）才具备验证 H-DS10 的资格；若 7B 长上下文迷失 → 换 Llama-3-8B 或开启 YaRN。
3. **工作流**：废弃手动上传，WorkBuddy 建立 git push / GitHub API 自动同步管道（用户配置一次 PAT）。

# 验收标准（How）

- H-DS10 门禁：7B 裸基线 3 位置命中 ≥ 2/3；通过线：混合保护 argmax ≥ 50% 且 cos ≥ 0.85。
- 数据存证：results/kaggle_7b_baseline.json、results/kaggle_7b_hybrid.json。
- 工作流：交付 one-click-sync——用户说「同步」即自动 push 本地最新 JSON/YAML/index.html 到 GitHub 并回报 Raw 链接。
