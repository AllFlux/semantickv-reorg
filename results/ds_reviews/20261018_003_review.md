# 理论背景（Why）

分析 DeepSeek（首席科学家/架构师/红队）与 WorkBuddy（研发总监/实验执行者）的「理论推演 ↔ 工程实证」双向闭环。数据是唯一裁判：当直觉被真实数据推翻时须立即承认。为维持高效闭环必须建立规则。

# 具体步骤（What）

角色分工：DeepSeek 负责 What&Why（假设、实验矩阵、归因、跨域迁移），无执行环境、结论须经 WB 数据确认；WorkBuddy 负责 How（代码、测试、采集、打包），不擅改契约、不美化结果、不把 CPU 结论当 GPU 结论。五大纪律：契约优先（--check-interfaces 全绿）、负面结果原样归档、环境隔离降级测试、参数冻结版本追踪、格式统一（数据表+结论+文件清单 / Why+What+How）。其他事项：交接协议（tar.gz+负结果 Markdown+悬而未决问题；接收方须明确「已复核同意」或「发现异常」）、防幻觉核查分工（WB 查包名/API，DS 查文献）、算力成本控制、第三方 Agent 预案（中间张量格式早冻结）。
