# 理论背景（Why）

上下文注入器：DeepSeek 无浏览器，无法渲染 HTML。看板若输出整页 HTML 或大段 JSON，解析效率极低。因此注入包必须是**高度浓缩的纯 Markdown 摘要**：纪律状态 / 活跃假设 / 最新实验核心指标 / 可按需拉取的 Raw 链接 / 待 DS 决策的问题。这使 DS 每次接手能立刻定位核心矛盾，并实现精准的按需深度审计。

E1.5 架构指令：针对 topk K=8 的 42.6% argmax 基线，继续加大 K 是算力浪费。混合保护只全量保留前 4（Sink）与最近 128（滑窗），中段用 K=4 代表。**关键风险在 Sink**：Sink 的 Key 范数极大，若中段群的 Top-K 与 Sink 拼接时没有独立 Attention Mask 隔离，Sink 会吸干所有 Query 的注意力，导致中段保留 token 无法被精确检索。

# 具体步骤（What）

- **看板升级（DS 上下文注入器）**：在 `index.standalone.html` 页面顶部加显眼模块「📦 给 DeepSeek 的上下文注入包」，内含 textarea + 一键复制按钮；内容由 JS 动态生成纯 Markdown（非 HTML），结构为：# 项目状态同步 → 📊 当前看板状态（纪律/活跃假设/最新实验/核心指标）→ 📁 原始数据 Raw 链接（真实 raw.githubusercontent.com 基址）→ 🚨 需要 DS 决策的问题。
- **Raw 基址落地**：`agora/config.json` 的 `raw_base` 置为 `https://raw.githubusercontent.com/AllFlux/semantickv-reorg/main/`，注入器与「复制 Raw 链接」产出的即为 DS 可直接拉取的真实链接。
- **E1.5 预研指令（转 WorkBuddy）**：在 `CompressedAttentionPatcher` 中对 Sink + 局部窗口 + 压缩中段实行「分段计算，最后求和」，确保中段保留的 4 个 Token 仍可被 Query 精确检索。

# 验收标准（How）

- 注入器验收：用户点击「一键复制」后得到一段极简 Markdown（无 CSS/网页冗余），含纪律状态、pending 假设数、最新实验指标、≥4 个真实可拉取的 Raw 链接、待决问题清单；DS 按此文本可无歧义接手。
- E1.5 可证伪目标：Qwen2.5-0.5B 下 Sink(4)+滑窗(128)+中段 K=4 时 **argmax 一致率 ≥ 50%**（H-DS7）；证伪线 < 45% → 判定 0.5B 瓶颈，直接上 Kaggle 7B。
- 数据存证预期落点：`results/real_model_v15_hybrid_protection.json`。
