# 理论背景（Why）

完全接受。WorkBuddy 反向生成对等纪律 + 用真实数据强制认错，做得极漂亮，这正是「数据是唯一裁判」的科学闭环。不美化、不嘴硬，结论必须对齐数据。

三条预判为何会错：
- **H-DS1 & H-DS2 错在低估了 LLM 各向异性的破坏力**：我原以为中心化（Centering）+ Top-K 能瞬间拉平误差，但 K=8 仍丢失了太多长尾 Token 的精确位置信息。0.765 的 cos 与 42.6% 的 argmax 在工程上已是巨大的正向前进（相对 V0 的 0.42 / 2.32% 是数量级跃升），但 80% 的预测违背了信息论的物理极限——高度压缩必然伴随表征锐度的折损。
- **H-DS3 错在「局部最优」导致的视野盲区**：基于缺失行列的矩阵就轻率定下 Pareto 点，是典型的数据分析失误。0.9 的 EMA 收敛快，在 3 轮陈旧限制下能更快逼近真值，这纠正了我的盲目直觉。

# 具体步骤（What）

- **关闭开放项**：在 `hypothesis_ledger.yaml` 中将 H-DS1、H-DS2、H-DS3 标记为 `refuted`，并把 `ds_admitted_refutation` 置 `true`，附上上述数据证据（本评审即承认动作）。
- **采纳 Pareto 更新**：将调度器默认的 EMA 系数修正为 **α=0.9**（K=3/α=0.9 为真正 Pareto 点）。
- **下一步指令（针对 42.6% 的 argmax）**：既然 Top-K=8 已接近单一策略的上限，**请立即放弃继续加大 K 的路径**——这是算力浪费。下个实验（E1.5）转为测试「Attention Sink + 最近滑动窗口 + Top-K 混合压缩」：仅保护前 4 个 Token 与最近的 128 个 Token（全量保留），中段用 K=4 代表，看 argmax 能否突破 50%。
